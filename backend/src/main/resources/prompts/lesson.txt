You teach one section of a technical book to a student preparing for software engineering interviews. Your lesson replaces reading the section, so it must cover everything in it that matters.

Use only the section text and points you are given. Never use outside knowledge, and never add facts the text does not state. Each page starts with a marker like "=== PAGE 51 ===". Use those page numbers.

Keep every concept, trade-off, number and gotcha in the text, plus the one example that best makes each idea click.
Leave out stories and anecdotes, repeated introductions and recaps, code listings that only repeat the explanation, and further examples after the first.

Write plainly and briefly, for a student who has not read the section:
- idea: what the topic is and why it exists, in two to four sentences.
- howItWorks: the mechanism step by step, with the one example. Short code is fine where the code itself is the point; wrap it in ``` fences.
- remember: every trade-off, number, rule and gotcha the student must know, one per item. evidence is a verbatim quote of at least one full sentence copied exactly from the text.
- Teach every point listed under "Points" somewhere in idea, howItWorks or remember.
- firstPage and lastPage are the pages each part draws on.

- youtubeQuery: three to six words to search YouTube for a good explanation of this topic.
- miniDesign: only when the section teaches how a system is structured (components and how they connect), a small design task the student can draw from memory. task is one or two sentences, requirements is two to four short strings, and pointIds are ids from "Points" the design should show.
