# Lessons Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clicking an Up next section opens a lesson that teaches it (text, diagrams, a YouTube search link, links to learned sections, a quick check), so the user no longer has to read the book cover to cover.

**Architecture:**
- **Backend** (`com.kaliyug.lesson`):
  - A `Lesson` row per map item stores generated content as JSON.
  - `LessonGenerator` builds it on a dedicated background thread:
    - one "lesson" AI call per budget-sized chunk of the section
    - one "coverage" AI call per chunk, which adds missing ideas as new grounded points
  - `LessonService` opens lessons, prepares the next two Up next sections, refreshes "Builds on" links on view, and picks the quick check.
- **Reuse:**
  - The quick check uses the existing question answer endpoint.
  - Finishing uses the existing Learned it endpoint, which from now on leaves already-answered points alone.
  - Mini designs use the existing design grader.
- **Frontend:** a new `/lesson/:id` page renders Mermaid diagrams through a lazily imported `mermaid` package.

**Tech Stack:**
- **Backend:** Spring Boot 4.1 / Java 21, Jackson 3 (`tools.jackson.*`), Spring Data JPA on H2.
- **AI:** Groq through the existing `JsonLlm`.
- **Frontend:** React 19, Vite 8, TypeScript 6, Vitest 5, React Testing Library, `@xyflow/react`, `mermaid@11.17.2`.

**Spec:** `docs/superpowers/specs/2026-10-30-lessons-design.md`

## Global Constraints

- **Grounding:** lessons use only the section's page text and its points, with no outside knowledge.
  - Every lesson part cites pages inside the section's range.
  - Every "What to remember" item passes `Grounding.evidenceFound` against the section's text; items that fail are dropped.
- **Kept / dropped line** (verbatim from the spec):
  - **Kept:** every concept, trade-off, number and gotcha, plus **the one example that makes each idea click**.
  - **Dropped:** stories and anecdotes, repeated introductions and recaps, code listings that only repeat the explanation, and further examples after the first.
- **Request size:** every AI request is at most `IngestionService.DEFAULT_MAX_INPUT_CHARS` (16,000) characters of user message.
- **The user's data survives:**
  - Schema changes are additive only: one new `lesson` table.
  - Enum columns use `@Column(columnDefinition = "varchar(32)")`.
  - Back up `data/kaliyug.mv.db` before the first run against real data.
- **Existing behaviour stays:**
  - pause switches, Skip for now, Remove
  - revision scheduling: CORRECT moves up a box; PARTIAL goes to box 1, due in 1 day; WRONG goes to box 0, due in 10 minutes
  - design problems
  - progress lowered only by wrong answers
- **Never commit** `.env`, `data/`, `*.pdf`, `node_modules/`, `target/`, `frontend/dist/` or `.superpowers/`, and never print `.env` values.
- **Commit messages** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- **Branch:** all work happens on branch `lessons`, created from `master`.
- **Commands:**
  - Backend tests: `cd backend && ./mvnw -q test`
  - Frontend tests: `cd frontend && npm test`
  - The bash safety check blocks `rm -rf`, so use `./mvnw clean` instead.

### Task 4: Lesson generation

**Files:**
- Create: `lesson/LessonGenerator.java`, `resources/prompts/lesson.txt`, `resources/prompts/lesson-coverage.txt`
- Test: `backend/src/test/java/com/kaliyug/lesson/LessonGeneratorTest.java`

**Interfaces:**
- Consumes: `BookText`, `PointWriter`, `Scheduler.onLearned`, `LessonRepository`, `LessonContracts`, `AiContracts.ExtractedPoints`, `JsonLlm`, `Prompts`, `ObjectMapper`, `TransactionTemplate`.
- Produces: `@Service LessonGenerator`:
  - Constants:
    - `static final String TOO_LITTLE_TEXT = "This section has almost no text the app can read (it may be mostly figures)."`
    - `AI_UNREACHABLE = "The AI is unreachable right now."`
    - `AI_UNUSABLE = "The AI kept giving unusable lessons for this section."`
    - `MIN_SECTION_CHARS = 200`
    - `MAX_DIAGRAMS = 2`
    - `READING_WPM = 180`
  - `public void generate(Long mapItemId)`:
    - Precondition: a `Lesson` row exists for the item.
    - Ends with that row READY (`contentJson`, `readingMinutes`, `newPointsFound`) or FAILED (`failureReason`), with `updatedAt` set either way. It never throws `LlmUnavailableException`.
  - `void setMaxInputChars(int)`: package-private, for tests; defaults to `IngestionService.DEFAULT_MAX_INPUT_CHARS`.

**Algorithm (the parts the tests don't fix):**
1. **Read** the item, its chapter and book, the section's plain text, and its points inside one `tx.execute`. All AI calls run outside transactions.
2. **Too little text:** if `Grounding.normalize(plain).length() < MIN_SECTION_CHARS`, the lesson is FAILED with `TOO_LITTLE_TEXT` and no AI call is made.
3. **Chunks:** `bookText.chunks(resource, start, end, maxInputChars * 11 / 16)`.
4. **For each chunk, the lesson call:**
   - The user message is:

     ```
     Section: <title> (pages a-b)
     Book: <book> · <chapter>

     Points (id | kind | text | pages):
     <the section's points whose firstPage is in the chunk; lines added while they fit in maxInputChars / 4>

     <chunk text>
     ```

   - Ask with `prompts.get("lesson")` for a `LessonReply`.
   - **Validation:** `idea` and `howItWorks` are both non-null, their text is not blank, and `start <= firstPage <= lastPage <= end` (section range).
   - **If invalid**, ask once more with this appended:

     ```
     Your previous reply was unusable: "idea" and "howItWorks" must both have text, and their pages must be within a-b.
     ```

   - **If still invalid**, throw `LlmBadReplyException`.
5. **Remember items** are kept only when the text is not blank, the pages are within the section, `firstPage <= lastPage`, and `Grounding.evidenceFound(evidence, plain)`.
6. **For each chunk, the coverage call:**
   - The user message is:

     ```
     Section: <title> (pages a-b)

     Lesson so far:
     <idea + howItWorks + remember texts, clipped to maxInputChars * 3 / 16>

     Points already known:
     <texts of the chunk's points, lines added while they fit in maxInputChars / 8>

     <chunk text>
     ```

   - Ask with `prompts.get("lesson-coverage")` for `ExtractedPoints`.
   - In one `tx`, `pointWriter.saveGrounded(item, reply.points(), plain)`.
   - Each saved point is appended to that block's remember list as `Remember(text, firstPage, lastPage, evidence)`.
   - If the item is learned, `scheduler.onLearned(p)` is called for each saved point, and their count is added to `newPointsFound`.
7. **Assemble** the content:
   - `diagrams`: the first `MAX_DIAGRAMS` non-blank diagrams across blocks, in order.
   - `leftOut`: the non-blank `leftOut` values joined with `" "`.
   - `youtubeQuery`: the first non-blank one, falling back to the item title.
   - `miniDesign`: the first one whose task is not blank. Its `pointIds` are filtered to ids of this section's points, de-duplicated; it is dropped when none remain. Requirements default to `[]`.
8. **Reading minutes:** `readingMinutes = max(1, ceil(words(all lesson text) / 180.0))`.
9. **Errors:** catch `LlmUnavailableException` → FAILED with `AI_UNUSABLE` if the exception is an `LlmBadReplyException`, otherwise `AI_UNREACHABLE`.
